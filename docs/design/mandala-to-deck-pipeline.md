# Design / Plan — Mandala → one deck pipeline

**Status**: Plan (design direction; implementation deferred to per-stage PRs)
**Date**: 2026-06-15
**Decisions source**: [ADR 0006](../adr/0006-mandala-to-deck-aggregation.md) (output-unit pivot).
**Reuses**: the single-video pipeline archived in
[`docs/archive/v1-single-video-per-deck.md`](../archive/v1-single-video-per-deck.md)
(ADR 0002 CV stages, ADR 0003 deck chain, ADR 0005 section bundle).

> **Goal restated (important).** The deck is **NOT generated by an LLM**. The goal
> is: **extract text (글) AND extract per-object data from frames (수식→LaTeX,
> 표→cells, 그래프→struct), then INTEGRATE both into one coherent set of data, and
> ASSEMBLE the `.pptx` deterministically from that data.** The LLM is a **placement
> helper only** (which content goes on which slide + connective prose); it never
> makes the PPTX file and never invents the object data (P1/P2).

---

## 1. Objective

One **mandala** (8 sectors × per-sector videos) → **one integrated `.pptx` deck**.
Not 8 stapled per-video summaries — a single coherent curriculum deck, built by
**integrating extracted data** (text + regenerated objects) across all videos.

## 2. Architecture

Two extraction branches feed one deterministic integration + assembly:

```
            ┌── (A) TEXT  ──────────────┐
 select ────┤                           ├── INTEGRATE ── PLAN ── ASSEMBLE ── persist
            └── (B) OBJECT DATA ────────┘   (deterministic)        (deck chain
                                                                    + LLM placement)
```

- **Deterministic layer (TS)**: resolve · select · integrate · plan · assemble-driver.
  No API dependency; identical in dev and prod.
- **Extraction**: text from v2 summaries (deterministic); object data from the
  reused CV tools (GPU).
- **LLM placement** (assembly step only): organizes the curated, integrated data
  into the deck recipe + writes connective prose. **dev = CC console (Write tool,
  no API); prod = injected LLM (Claude Sonnet via OpenRouter), one call per deck
  (single-deck service call, not bulk).** `OPENROUTER_API_KEY` is prod-only.
- **Deck assembly + validation** is the vendored `deck/` chain (deterministic
  build → `validate_deck` → FAIL-feedback loop). The PPTX is assembled by code.

## 3. Pipeline (full, end-to-end)

```
[0] RESOLVE        mandala_id → 8 sectors · videos[] · per-video mandala_relevance_pct   (new, DB read)
        │  fan-out per video
[1] FETCH v2 ×N    per-video v2 load + gate                                              (♻ v2-reader)
        OUT: sections[]{from_sec,to_sec,title,summary,key_points,relevance_pct}
             atoms[]{type,text,timestamp}
        │
[2] SELECT         score = video mandala_relevance × section relevance_pct
        (new, det.) → keep top sections → group into the 8 sectors
        OUT: selected sections + each [t_start,t_end]
        │
        ├──────────────── (A) TEXT branch ───────────────┬──────────── (B) OBJECT branch ────────────┐
        ▼                                                 ▼
[3A] TEXT EXTRACT                                    [3B] FRAME + OBJECT EXTRACT (selected windows only)
   selected sections: summary + key_points              a. acquire   yt-dlp (Mac Mini proxy → S3)       ♻
   + in-window atoms (fact/tip)                          b. frames    grab the selected window only       ♻ frames.py
   → per-sector content text                             c. YOLO      DocLayout-YOLO boxes (WHERE)         ♻ figure_extract
   (♻ text, deterministic)                               d. Qwen3-VL  kind classification (WHAT)            ♻ (GPU)
                                                         e. experts   equation→LaTeX · table→cells ·        ♻
                                                                      chart/graph→struct
                                                         f. redraw    vector / ≥300 dpi regen               ♻ redraw.py (incomplete)
                                                         → object data {figure_id, kind, struct/latex, t}
                                                         (cache: slide_figures / slide_keyframes)
        └──────────────────────────┬──────────────────────────────────────────────┘
                                   │  text + object data (time-aligned)
[4] INTEGRATE      per sector: merge text + object data; cross-video concept/figure dedup   (new, det.)
        OUT: mandala bundle  sectors[] → sections[](text) + figures[](objects) + shared_figures
             (no raw caption, no frame pixels — text / struct / LaTeX / figure_id only)
        │
[5] PLAN           8 sectors = 8 chapters + slide-budget allocation + single deck type        (new, det.)
        │  integrated content material
[6] ASSEMBLE       LLM placement (dev=console / prod=API, 1 call) → deck chain builds the
        │          PPTX deterministically → validate_deck → FAIL-feedback loop                (♻ deck chain)
        ▼
[7] PERSIST        .pptx + appendix.md · slide_decks(mandala_id) + slide_* writes only        (♻ slide-repo)
```

### Stage table

| # | Stage | Core | Tools | Kind |
|---|---|---|---|---|
| 0 | resolve | unpack mandala structure | mandala-resolver | det. |
| 1 | fetch v2 ×N | load + gate summaries | v2-reader ♻ | det. |
| 2 | select | relevance rank · sector group | mandala-selector | det. |
| 3A | **text extract** | summary + key_points + atoms | (text) ♻ | det. |
| 3B | **object extract** | window frame → equation/table/chart data | frames/YOLO/Qwen/experts/redraw ♻ | GPU |
| 4 | **integrate** | merge text + objects · cross-video dedup | mandala-integrate | det. |
| 5 | plan | chapters · budget · single type | mandala-planner | det. |
| 6 | **assemble** | LLM placement + deck build + validate | deck chain ♻ | LLM + det. |
| 7 | persist | .pptx + slide_* | slide-repo ♻ | det. |

### Pipeline properties
1. **Two first-class extraction branches** — text (A) and object data (B); neither
   is dropped. Both converge at INTEGRATE.
2. **Selection precedes extraction** — object extraction (3B) runs only on the
   sections chosen at (2), so the single-video CV *front-end selection machinery*
   (scenedetect / pHash / pre-select / Qwen-select) is **not needed**: the relevant
   timestamps are already known. CV grabs the known window directly.
3. **Integration is deterministic** — time-aligned merge + cross-video dedup.
4. **Assembly is deterministic** — the deck chain builds the PPTX; the LLM only
   places content + writes connective prose (dev console / prod single API call).
5. **Reuse vs new** — new code is deterministic TS (resolve / select / integrate /
   plan); the heavy CV tools, the deck chain, and the DB layer are reused as-is.

## 4. Data grounding (verified against `src/types/slide-manifest.ts`)

- `V2Section { from_sec, to_sec, title, summary, relevance_pct (0–100), key_points[] }`
  — per-section relevance exists.
- `V2Atom { type (fact/argument/tip), text, timestamp }` — **text only**; v2 atoms
  carry NO figure/table/equation struct data.
- ⇒ **All object (equation/table/chart) data must come from the CV branch (3B);**
  there is no atom shortcut. Text is rich (sections + key_points + atoms).

## 5. Implementation sequencing (the whole pipeline is the target)

The complete pipeline (both branches) is the design. Practical build order — the
deterministic spine and text branch are buildable locally now; the object branch
depends on GPU + finishing the CV tools:

1. **Spine + text (local, no API)** — stages 0,1,2,3A,4,5,7 with console-authored
   placement (stage 6 dev path). Produces an integrated mandala deck from text.
2. **Object branch** — wire 3B (targeted CV) into INTEGRATE; finish the incomplete
   CV tools (e.g. `redraw.py`). Objects then attach by time alignment.
3. **Prod assembly** — switch stage 6 placement to the injected LLM (`SLIDEGEN_MODE=prod`).

This is build sequencing, **not** a reduced scope: the object branch is part of the
pipeline, not optional in the final product.

## 6. To confirm before coding

- **Section `relevance_pct` semantics** — relevance-to-mandala vs importance-within-

  relevance_pct` (as drawn). Verify against a real DB row / upstream.

## 7. Open questions (decision / measurement-gated)

Slide-budget rule (whole-deck fixed vs per-sector) · single deck-type selection
rule · cross-video figure/concept dedup threshold (embedding similarity —
measurement-gated) · multi-video bundle shape (ADR 0005 `sections[]` extended to
`sectors[] → videos[] → sections[]`) · sector/video ordering · low-content sector
orphan handling (recall-first, mirror ADR 0005 D3).

## 8. Risks

- **CV tools incomplete** (`redraw.py` etc.) → object branch lands after the spine;
  the spine ships an integrated deck meanwhile.
- **Token blow-up** on a large mandala → the deterministic select (2) + dedup (4)
  bound the integration input.
- **Relevance-semantics misread** → §6 confirmation gates stage 2.
- **Hard rules** — `slide_*`-only writes; Insighta tables read-only; LLM bulk-API
  ban (dev console / prod single call); raw frame pixels never embedded (P2).
